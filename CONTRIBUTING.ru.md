# Как внести вклад

Упражнения выполняются в личном форке и решения хранятся исключительно там. Исходный репозиторий **не** предназначен для выполненных решений.
В основной репозиторий отправляйте PR с исправлениями заданий, документации или переводов, тестами для случаев, которые ещё не покрыты, улучшениями инфраструктуры и новыми заданиями.

## Откройте первый PR

1. Сделайте форк [`Fleack/build-your-stl`](https://github.com/Fleack/build-your-stl) и клонируйте его. Создайте ветку для изменения, например `git switch -c fix/find-tests`.
2. Сделайте одно связанное изменение и [проверьте его локально](#проверьте-изменение).
3. Создайте коммит с осмысленным названием и отправьте ветку в свой форк. Откройте PR из этой ветки в `Fleack/build-your-stl:master`.
4. Опишите, что изменилось, зачем и как вы это проверили. Для новых тестов укажите, какое поведение не покрывали существующие проверки.

## Проверьте изменение

- Для задания соберите и запустите его тесты по инструкции в README задания. Новые или изменённые тесты проверьте на реализации, которая соответствует условию.
- При изменении тестового фреймворка или общей конфигурации сборки запустите [самопроверки фреймворка](infrastructure/test/README.ru.md#самопроверка-фреймворка).
- При изменении документации проверьте относительные ссылки и обновите обе языковые версии.

Чтобы запустить те же тесты с реализациями std, что и в CI, используйте отдельный каталог сборки.

```sh
cmake -S . -B out/reference -DBYS_REFERENCE_TESTS=ON
cmake --build out/reference --parallel
ctest --test-dir out/reference --output-on-failure
```

В этом режиме тесты упражнений используют эталонные реализации. Также запускаются самопроверки фреймворка. Свою реализацию проверяйте по инструкции в README задания.

## Соблюдайте стиль кода

Форматируйте изменённые C++ файлы по правилам [`.clang-format`](.clang-format). Используйте `snake_case` для функций, переменных и имён файлов, а `PascalCase` для вспомогательных типов. Сохраняйте имена стандартной библиотеки в API заданий, например `bys::vector` и `value_type`. Называйте цели тестов `<задание>_tests`, а отдельные тесты — `<задание>.<сценарий>`.

## Добавьте задание

- Сделайте задание независимым от других заданий и используйте C++20 и тестовый фреймворк проекта.
- Добавьте краткий README на английском и, по возможности, на русском, заголовок с заготовкой и отдельную цель CMake для тестов.
- Проверьте заявленное поведение и граничные случаи. Добавьте проверки типов, `constexpr` и сложности, если этого требует контракт.
- Зарегистрируйте задание и его заголовок стандартной библиотеки в [`exercises/CMakeLists.txt`](exercises/CMakeLists.txt). Укажите дополнительные имена из стандартной библиотеки, которые используют тесты. Добавьте ссылку в [английский](EXERCISES.md) и [русский](EXERCISES.ru.md) каталоги.

## Ревью и слияние

Владелец репозитория начинает ревью PR после прохождения обязательных проверок CI. Для слияния также нужны одобрение владельца [@Fleack](https://github.com/Fleack) и соблюдение правил стиля и именования выше.

CI проверяет форматирование C++ через clang-format 22, имена в C++ через clang-tidy 22 и ссылки на файлы репозитория и заголовки Markdown. Тесты запускаются на Ubuntu 26.10 с GCC 16.2 и Clang 22.
